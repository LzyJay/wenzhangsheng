## 2 · 实跑结果（原文）

### 2.1 起窗口方式（有偏差，须记录）

计划书写的是 `Get-Process electron | Stop-Process -Force` → `cmd /c scripts\launch-debug.cmd`。
本会话环境**沙箱直接拦截 `cmd.exe`**（Bash 与 PowerShell 两条通道都拒），故改为**等价复刻** `launch-debug.cmd` 的动作：

```
electron.exe <repo> --remote-debugging-port=9229 --no-sandbox --disable-gpu
             --user-data-dir=C:\Users\Administrator\AppData\Local\Temp\wcs-a2-cdp\ud
```

- 前三个参数与 `launch-debug.cmd` 等价（同一 9229 端口）；
- **`--no-sandbox --disable-gpu` 是本沙箱的生存必需**：不加时 GPU 进程反复 `exit_code=1`，
  Electron 随后 `FATAL: gpu_data_manager_impl_private.cc(449)] GPU process isn't usable. Goodbye.` 自杀，
  窗口起不来（已实测三次）。**这两个开关不是项目改动**，只是本会话的启动方式；
- **`--user-data-dir` 指向临时 ASCII 目录**，并把主人存档**副本**放进去当老档 —— 见 §5 存档偏差申报。

- #2：V4.7「丹房自动补货」由主循环 `restockTick` 每拍把每种丹补回**常备 1 枚**（`main.js:3990`，开关 `settings.autoBrew`）。
  服下护劫丹后库存会被立刻补回，**原「剩 0 枚」断言永远看不到 0**。本段测的是「服下即消耗」，
  故先关补货开关再断言 —— 断言强度不变，只是把可观测条件造出来。末尾随快照还原。
- #4~#8：`P = clamp(P_base + 准备合计 + 修为积累 + 顺天值, 0.05, 0.95)`，其中 `P_base = clamp(0.35 + 0.30/fk, 0.10, 0.90)`。
  实测裸基准仍是 0.59（fk=1.25 未变），但主人存档里**持有镇雷法宝(+8%) + 出战灵兽主战+辅助(+10.5%) + 顺天值(+3%)**，
  所以 `p0` 是 0.805 而非 0.59。原来那三个绝对值是**某个存档快照**，换档/换持有物就红。
  改成断「护劫丹自己贡献 +0.10」「P 与准备合计同幅抬升」「成率走 P³+3P²(1−P) 公式」——
  测的是**契约**，与存档持有物无关，且比原断言更难蒙混。
- #9：引雷有 `P³+3P²(1−P)` ≈ 77%~97% 的概率**直接冲关成功**；成功后本级不再是渡劫关口（`trialNode < 0`），
  渡劫面板打不开、突破判定不再命中渡劫、气泡自然不弹 —— 原顺序把三条断言放在引雷之后，**随成率浮动误红**
  （原口径 77% 成率下也本就是大概率红）。挪到引雷之前，断言一条不减。
  另：④ 静养结束时面板是**开着**的，而快捷条键是 toggle，故先关面板再测「键→面板」（新增 `panelClosedBeforeKey` 前置断言）。
