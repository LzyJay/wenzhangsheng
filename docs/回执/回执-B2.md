**口径**：与 B1 回执一致——「当量 h」＝1 小时等效基准产出；折灵石走 `stoneHourly(L47)=1102`；分母取**严格 24h/日**；B2 各量全部按压缩日历（1 现实分钟 = 1 游戏天 → 每现实日 ≈ 205.7 个「7 游戏天轮次」）放大后核算。

**结论**：
1. **中期档带内**（8.9% ≤ 15%）；**满配档仍超**，但超带部分与 B1 结论一致来自**俸禄表**（2.0/3.0h/日），B2 的灵石增量上限仅 **+0.7pp**（若带宝材料不卖而用于炼丹则近 0）。单点旋钮：`DISC_EVENTS.chance`（0.03）与 `treasureMat` 权重——若主人 24h 实测偏高，把 chance 降到 0.02 或把带宝权重归 0 即可，都是 data 层单值。
2. **设计稿「大比＋灵石」必须裁除的量化证明**：设计稿口径 1.0 当量 h/届 × 205.7 届/现实日 = 205.7 h/日 ≈ **857% of 24h**——压缩日历下任何「周常灵石奖」都会 ×205，本批改发头衔/魁首荣誉。若主人想要灵石味，建议「每现实周（10080 现实分钟）一届」的另一种日历口径，需拍板。
3. 供奉存在一个**有界手点回路**：灵纹符纸商店 60 贡献/2 份 → 供奉 48/份，每轮净赚 ≤180 贡献——需每 7 现实分钟手点一轮（一日 205 次），量级 ≈ 任务贡献线的 18%（上限），且自动系统不参与；如嫌烦可把 `OFFERING.rate` 降到 1.0（单点旋钮）。
