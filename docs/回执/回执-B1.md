1. **中期档在带内**（宗门线 8.6% ≤15%），**弟子线满配被 2.0h/日 硬顶压住**（原始 10.4h/日 → 2.0）；封顶旋钮**已由主人 2026-09-19 拍板**由设计稿「后期日均 2.4h」下调至 **2.0h/日**（为俸禄腾出 1/3 空间）。
2. **严格 24h 分母下，化神+首座起宗门线超 15%（16.7% / 20.8%）**。归因：**超出的部分主要来自既有「俸禄」而非弟子线**——俸禄在首座档 2.0h/日 = 8.3%、掌门档 3.0h/日 = 12.5%，弟子线本身恒为 **8.33 个百分点**（2.0/24 = 8.33%）。
3. **单点旋钮**：`src/data/disciples.js → DISCIPLE_CAP_H_PER_DAY`（现 **2.0**；若仍要「首座档也落 15% 内」可再降至 **≤1.6**，但掌门档仍会超，根因在俸禄表，需主人一并拍板）。**次级旋钮**：`POSTS[].hourPerDay`（0.3 / 0.25）、`POSTS[].contribPerH`（40 / 20）。
4. **设计库口径复核**：按设计库自己「合计 6.4h/日 ≈15%」隐含的分母（≈42.7h/日），本实现满配 **12.7%** 在带内——两口径结论相反，根因是「总收益」分母定义未定稿（§4.4 遗留待办 3）。**建议合流 M2 的首次全线占比归因复核时以实测读数定案**。
