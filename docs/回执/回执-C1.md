## 4 · 静态量级预估（数值型模块必填）

基准：内门档 L47（`stoneHourly(47) ≈ 1102 灵石/h 当量`）；一轮刷新日 = 30 游戏天 ≈ 现实 30 分钟。

| 项 | 数值 | 算法/来源 |
|---|---|---|
| 兽潮频次 | 0.4 次/现实小时 | 150 游戏天一轮 ≈ 2.5h（5×REFRESH_DAYS，设计库 §1.5「每 5 天」折算） |
| 兽潮单次产出 | 参与 0.05h / 中坚 0.07h / 前列 0.09h 当量 + 妖丹 1/2/3 + 掉蛋 5%/15%/30% | `WAVE.rewardH/yaodan/eggChance` |
| 兽潮每小时 | ≈0.028 h当量/h（中坚典型）≈ 31 灵石/h | 0.4 × 0.07 |
| 大比频次 | ≈0.286 届/现实小时 | 210 游戏天一届 ≈ 3.5h（设计库 §2.1「七日循环」折算） |
| 大比期望产出 | ≈0.021 h当量/届（§2.3 表÷48 × 名次分布）→ ≈0.006 h当量/h ≈ 7 灵石/h | 名次档 0.4~4h/周 ÷ 48，rand 均匀下期望名次 ≈4.5 |
| **本模块合计** | **≈0.034 h当量/h ≈ 0.82h/日**（恰合设计库自校验「兽潮周均 ≈0.8h/日」） | 0.028 + 0.006 |
| 既有灵兽被动产出 | 0.025~0.05 h当量/h（单兽 0.2h/日 ~ 满编 1.2h/日） | 既有 `productionHours` 口径 |
| **灵兽线合计占比** | **≈5.1%~7.3%**，落在 §七 目标带 5~8% | 以设计库自校验锚点 5% = 1.4h/日 = 0.058 h/h 为分母 |

**结论**：在带内，无需降档旋钮。两点供拍板：① 设计库原文「大比奖励计入宗门线预算」与任务卡硬口径「归因走既有 beast 线」不一致，本批按任务卡走 beast 线（占比账仍按灵兽线 5~8% 控制，不双计）；② 长老档冠军单届当量被档位系数 ×3 放大（方差大），设计库原文的「资源封顶 10h/周」首批未做，若实读数偏高可在 C2 加周封顶。
